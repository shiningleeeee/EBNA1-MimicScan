# 把 pipeline 当证伪器用：检验 Almulla 2026 的 91 个共享五肽

**日期**：2026-10-22
**被检验的主张**：Almulla AF, Normatov MG, Supasitthumrong T, Maes M. *Immun Inflamm Dis* 2026 May;14(5):e70445，doi 10.1002/iid3.70445，PMID 42125999，PMC13169152。他们比对了 33 个 EBV/HHV-6 蛋白与 10 个人 CNS 抗原，报告 **91 个共享五肽（EBV 42 / HHV-6 49）**，并据此讨论"共享五肽提示病毒–CNS 自身免疫关联"。
**被检验的那句话**：这 91 个共享五肽，是否多于把组成固定住之后应有的数量？

---

## §0 一句话结论

**不多。** 在全部 330 个蛋白对上穷举重算，得到 **99** 个共享五肽（论文报 91，是我们 99 的子集）。把同样这 43 条序列的**氨基酸组成固定、只打乱顺序**再算，全局洗牌平均给 **68.6**（p=0.0015，确实有 1.44× 超额）；但一旦零模型**保留局部组成**（10-aa 或 20-aa 窗口内洗牌），期望变成 **97.1 / 90.7**，p = **0.44 / 0.22**——超额消失。而且**没有任何一对蛋白是例外的**：实测最高一对是 4 个共享五肽，而洗牌最高能给到 9–16 个。

第二层检验更直接：换成 10 个**长度与组成都匹配的随机人类蛋白**，与同样 33 个病毒蛋白共享 **80.6 ± 11.8** 个五肽（范围 48–116，200 次抽样里 11 次 ≥ 99）。**CNS 抗原这个特定集合并不特殊**（p = 0.060）。

### 1.4 逐条验证 91 个五肽是否真的同时在两条序列里

这一条最要紧——论文报的坐标/肽段有没有错。

**结果：90/91 在双方序列里都能精确找到。1 条找不到。**

| 病毒 | 病毒蛋白 | CNS | 五肽 | 在病毒侧 | 在 CNS 侧 | accession |
|---|---|---|---|---|---|---|
| EBV | gE | MAG | `LTSIL` | **不存在** | 存在 | P09259 / P20916 |

查下去，原因很清楚，而且是个**实质错误**：

```
P09259 的真实身份 = sp|P09259|GE_VZVD Envelope glycoprotein E
                    OS=Varicella-zoster virus (strain Dumas) OX=10338
```

**P09259 是水痘–带状疱疹病毒（VZV）的 gE，不是 EBV 的蛋白。** 论文 Table 1 把它列在 Epstein–Barr virus 名下。EBV 不编码 gE。

而 `LTSIL` 真正出现的位置是 **HHV-6 主要衣壳蛋白 P17887 第 283 位**——那是 Table 2 里**另一行**（HHV-6 MCP ↔ MAG：`LTSIL, EVEVS`）。所以这一行很可能是**重复计数 + 归属错误**。

### 1.5 论文报告的结构

67 个不同的蛋白对，91 个五肽：48 对只有 1 个，15 对有 2 个，3 对有 3 个，**1 对有 4 个**（EBNA1 ↔ SYN1：`GGSGG, PGPGP, GPGPQ, PQPGP`）。

## §2 检验一：组成固定之后，99 还多吗

### 2.1 穷举重算（不依赖论文的分对）

在 33 × 10 = **330** 个蛋白对上，用精确 5-mer 集合交集重算：

| 统计量 | 实测 |
|---|---|
| 至少共享 1 个五肽的蛋白对 | **69 / 330** |
| 全部 330 对累计的不同五肽数 | **99** |
| 单对最高 | **4**（EBNA1 ↔ SYN1） |

论文报 91，我们算出 99：**论文报的是我们这 99 里的一个子集**，方向一致，说明解析没错。

### 2.2 三个零模型（B = 2000，seed 42）

每个零模型都只打乱**顺序**、保留**组成**，差别在于"组成"保留到多细：

- **global**：整条序列均匀随机排列
- **window10 / window20**：在互不重叠的 10 / 20 aa 窗口内各自洗牌

| 零模型 | 有共享的蛋白对（实测 69） | 累计共享五肽（实测 99） | 单对最高（实测 4） |
|---|---|---|---|
| global | 54.6，p = 0.0150 | 68.6，p = **0.0015** | 洗牌最高 **9**，p = 0.4018 |
| window10 | 63.1，p = 0.1974 | **97.1**，p = **0.4388** | 洗牌最高 **14**，p = 0.9925 |
| window20 | 62.0，p = 0.1624 | 90.7，p = 0.2214 | 洗牌最高 **16**，p = 0.9530 |

三句话：

1. **全局洗牌下确有超额**：99 vs 68.6，1.44×，p = 0.0015。这一步我不隐瞒。
2. **但只要保留局部组成，超额就没了**：99 vs 97.1（p = 0.44）和 90.7（p = 0.22）。也就是说这 1.44× 完全来自**局部组成聚集**（SYN1/SYN2 的脯氨酸富集段、EBNA1 的 Gly-Ala 重复、MOBP 的低熵），不是残基顺序。
3. **没有一对蛋白是例外的**。实测最强的一对是 4 个共享五肽，而随机洗牌能造出 9–16 个。论文最得意的那个例子（EBNA1 ↔ synapsin-1，4 个）在 window10 零模型下 p = 0.99。

### 2.3 解析式交叉验证：组成本身就是 2 倍

如果 20 种氨基酸等概率，任意两蛋白的期望共享五肽数 ≈ L₁L₂/20⁵。对 330 对求和：

```
均匀组成期望                31.9
真实组成（洗牌实测）         68.6      ← 2.15×
```

**什么都不做，只把氨基酸组成从"均匀"换成"真实蛋白的组成"，期望就从 32 涨到 69。** 组成最低的几个蛋白是 P03211 EBNA1（H = 3.17 bits）、Q13875 MOBP（3.70）、P12978 EBNA2（3.72）、P52460 HHV-6 U83（3.76）。这些低熵蛋白就是共享五肽的主要制造者。

## §3 检验二：CNS 抗原这个集合特殊吗

论文的落点是"病毒 → **CNS** 自身免疫"，所以真正的问题是：换成别的人类蛋白，共享数会变少吗？

**设计（两个混淆都控住）**：为 10 个 CNS 抗原各建一个候选池，要求 ①长度在 ±15% 内；②氨基酸组成 L1 距离落在该长度池最近 20%；从池中均匀抽 1 个，凑成一组 10 个，与同样 33 个病毒蛋白算共享五肽。重复 200 次。

| | 数值 |
|---|---|
| CNS 抗原实测 | **99** |
| 匹配随机人类蛋白（均值） | **80.6 ± 11.8** |
| 范围 | 48 – 116 |
| p95 | 99 |
| ≥ 99 的抽样次数 | **11 / 200** |
| **p（单侧）** | **0.060** |

**任意 10 个长度与组成匹配的人类蛋白，平均就能拿到 81 个共享五肽，最高 116 个。** CNS 抗原集合排在第 94 百分位——不显著。

换句话说：论文报的 91，比"随便挑 10 个人类蛋白"的期望（81）只高 12%，而且低于随机抽样的最好值（116）。

## §4 这个结论站到什么程度

**能说的：**

1. 论文报告的 91 个共享五肽，**在保留局部组成的零模型下完全不超额**（p = 0.22–0.44）。
2. **没有任何一个蛋白对**的共享五肽数超过随机洗牌能产生的水平（实测最高 4，洗牌最高 9–16）。
3. **CNS 抗原集合与匹配的随机人类蛋白不可区分**（p = 0.060）。
4. 论文 Table 1 有一处**实质数据错误**：把 VZV 的 gE（P09259）列为 EBV 蛋白，并据此报了一条无法在双方序列中验证的五肽。
5. 91 个五肽里有 **90 个确实同时在两条序列里**——论文的序列比对本身没错，错的是**从"共享五肽存在"到"提示分子模拟"这一步**。

**不能说的（必须写清楚）：**

1. 我**没有**检验他们的 IEDB 免疫原性评估与结构同源分析。这两块是独立的证据线。
2. 五肽共享只是**邻近度代理**，抗体并不识别 5-mer。本章不能推出"这些蛋白之间不可能交叉反应"。
3. 我的零模型保留了单残基组成与（在窗口版本下）局部组成，**没有保留二肽组成**。更强的零模型只会让超额更小，不会更大。
4. 91 vs 99 的差异可能来自他们对同源蛋白集的选择或去重规则；我按 Table 2 逐行解析，未做额外删减。

**这个结论真正说明的事：** 一篇 2026 年、用 AlphaFold + PyMol + Alignmentaj + IEDB 四个工具做的 mimicry 研究，其核心数字（91 个共享五肽）在组成零模型下就是一个普通值。这不是他们做得不认真——是**"共享五肽"这个统计量本身没有分辨力**。这和我们自己项目里 `margin_z` 的失败是同一件事的两面：三个已发表的真 mimic 在序列统计量上也只是中位数水平（`REPORT_step7_calibration_failure.md`）。
